# Technical notes

## Commands

Requires Node.js 24. PostgreSQL needs no install: dev and tests start an embedded one.

| Command | What it does |
|---|---|
| `npm install` | Install dependencies |
| `npm run dev:all` | Local database on port 54329 plus the web app on http://localhost:3000. Migrations run automatically. In the desktop app: preview config `web` |
| `npm test` | Unit, database, API, golden and message-catalogue tests (about 30 s) |
| `npm run typecheck` | Both TypeScript projects |
| `npm run e2e` | Browser tests in the installed Chrome, on port 3100 (about 8 min). **Stop `dev:all` first:** Next.js allows one dev server per folder |
| `npx playwright test e2e/passkeys.spec.ts --project=desktop -g "name"` | One browser test |
| `npx next build` in `apps/web` | Production build. Needs the three variables below; dummy values are enough |

**Git:** in PowerShell, `git` may not be on PATH; use `C:\Program Files\Git\cmd\git.exe`. Git Bash finds it. Remote: `github.com/kirilshishkovvvv-hub/fintrack` (private), branch `main`.

## Configuration

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection |
| `AUTH_SECRET` | At least 32 characters. Also keys the login-throttle hashes |
| `APP_ORIGIN` | The app's own origin. CSRF checks, passkey domain, cookies |
| `EMAIL_MODE` | Only `log` so far. Production throws until Scaleway is added |

The server validates these at startup (`apps/web/src/server/app.ts`). `npm run dev:all` sets them itself.

**Local files, all under the gitignored `.pgdata/`:**

| Path | Contents |
|---|---|
| `cluster/` | The dev database. Safe to delete; it's rebuilt with empty data |
| `dev-secrets.json` | Dev database password and auth secret |
| `dev-account.json` | A local test login. **Never repeat it in chat.** The account must be created again after `cluster/` is deleted |
| `e2e-db.json`, `e2e-server.log`, `e2e-results/` | Browser test run files |

In dev, security emails, including verification links, print to the server log as `[dev-email] kind for address: url`.

## Migrations

- Forward-only SQL files in `packages/db/migrations`, run once each in name order, inside a transaction (`packages/db/src/migrate.ts`). Tracked in `ops.schema_migrations`.
- **Never edit an applied migration.** Add a new one. Next free number: `0010`.
- `0002_auth.sql` was generated by `scripts/generate-auth-migration.ts` at Better Auth 1.7.11. Later auth columns are hand-written in 0006 and 0008, so regenerating would produce a different file: review any diff.
- Migrations refuse a database that isn't UTF-8. Local clusters use `--encoding=UTF8 --locale=C` and `io_method=sync` (`packages/db/src/test-database.ts`).
- `migrate.ts` isn't exported from `@fintrack/db`, or the Next.js bundler tries to package the migrations folder.
- Each new table needs: `workspace_id`, composite foreign keys, forced row-level security with the `workspace_isolation` policy, grants, and a place in the purge order in `packages/db/src/deletion-store.ts`.

## Patterns to follow

- **Requests:** `dispatch` → `authenticate` → route handler → `inWorkspace` (`packages/api/src/app.ts`). Every financial query takes `workspaceId` explicitly, as well as row-level security.
- **Writes:** `idempotentWrite` for POSTs; `requiredVersion` (If-Match) for edits.
- **Run database queries in sequence on one connection,** never with `Promise.all` inside `withWorkspace`.
- **Errors:** RFC 9457 with a stable code. Add the code to `ProblemCode` (`http.ts`), and to `TRANSLATED_CODES` in `apps/web/src/lib/api.ts` with a text in `en.json`.
- **Golden scenarios:** data in `packages/golden/src/scenarios`. The database run replays `MemoryBook.events`, so a new operation needs a branch in both the memory runner and `golden.db.test.ts`.
- **Web pages:** client components with `useApiData`; `notifyDataChanged()` after a change; `LoadError` on failure. Dates and amounts come from the server.

## Dependencies with a catch

- **Better Auth packages are pinned together** at 1.7.11, along with `@better-auth/core`, `better-call` and `@better-fetch/fetch` (T-50). Upgrade them as one, or npm reports a conflict.
- **Passkey plugin:** it sets `requireUserVerification: false`. Our `afterVerification` hooks in `auth.ts` are what enforce the check. Keep them, and re-run the mutation check after any upgrade.
- **`rememberMe`:** Better Auth treats a missing value as true, and doesn't slide the expiry when it's false. `auth.ts` normalizes it, and the session create hook sets the expiry; idle limits are enforced in `authenticate` through `lastActiveAt`.
- **embedded-postgres** is a beta used only for dev and tests. Its Windows postinstall is a no-op and isn't enabled.
- **Versions:** pin exact versions at least two weeks old.
- **`Client.call` in tests** parses JSON only when the response says it's JSON.

## Limitations and troubleshooting

| Symptom | Cause and fix |
|---|---|
| Blank page, `EPERM ... rename ... .next` | Windows file lock; cause not confirmed. Stop the server, delete `apps/web/.next`, restart |
| New API route answers 404 in dev | The server keeps one app instance across hot reloads (`globalThis`). Restart the server. A migration needs a restart too |
| `The database uses WIN1251 encoding` | A cluster from before the UTF-8 fix. Delete `.pgdata/cluster` |
| Dev server won't start: PostgreSQL error | Leftover `postgres.exe` from an earlier run. Find them with `Get-CimInstance Win32_Process -Filter "Name='postgres.exe'"` and stop those whose path is under `embedded-postgres` |
| 429 on sign-in during manual testing | Five attempts per 15 minutes per source (T-11), or the per-account delay. Browser tests send their own `x-forwarded-for` |
| `getByRole('alert')` finds the wrong element | Next.js has its own hidden route announcer. Scope to `main [role=alert]` |
| A passkey test passes without proving anything | Chrome can refuse before the server is reached. Test with a tampered client, and confirm that it fails with the check removed |
| Editing with `String.replace` corrupts text | `$` followed by a backtick is special in a replacement string. Use a replacer function |
| Long scripts fail in the Bash tool | Very long inline heredocs can fail to parse. Write the file with the Write tool |

PowerShell 5.1: `Set-Content -Encoding utf8` adds a BOM; `[id]` in a path is a wildcard for `Select-String`.
